# Аналитика «Берега»

## Пиксель VK / Top.Mail.Ru 3805761

В `index.html` подключён локальный `analytics-consent.js`. Яндекс Метрика и
Top.Mail.Ru загружаются только после явного согласия. До выбора и при отказе
счётчики не загружаются. Noscript-пиксели удалены, чтобы не обходить согласие.
При согласии учитывается текущая страница, внутренние переходы — `sendPageView`.
Загрузчик защищён от повторного подключения. Изменения ответов и открытие
черновиков не являются просмотрами отдельных страниц.

На сайте нет авторизации и собственных идентификаторов пользователей.
Поэтому `pid: "USER_ID"` исключён, а не заменён случайным значением. ID локальных
случаев, телефоны, почта и другие сведения не используются для синхронизации.
Обычная идентификация браузера самим счётчиком не заменяет ID аккаунта сайта.

## Слой данных

Название в настройках пикселя: **`dataLayer`**, с таким регистром.
До согласия события не накапливаются и не отправляются задним числом.
Массив создаётся до загрузки счётчиков; существующее содержимое не перезаписывается.
В него отправляются только объекты `{event: "название"}`:

| Событие | Условие |
| --- | --- |
| `onboarding_start` | Первый ответ, один раз за прохождение |
| `plan_received` | Первое получение нового плана после завершения опроса |
| `plan_step_done` | Переход задачи из невыполненной в выполненную |

Яндекс Метрика 113661127 получает те же события через `reachGoal`, как раньше.
Для VK используется только слой данных: дополнительных вызовов `reachGoal`
Top.Mail.Ru нет, чтобы не создавать второй канал для одной конверсии.
В события не передаются ответы, тексты полей, номера обращений, идентификаторы
случаев, названия конкретных шагов или содержимое документов.

## Что проверить владельцу в VK Рекламе

1. В настройках пикселя включить сбор событий из слоя данных и указать `dataLayer`.
2. Синхронизацию пользователей через ID аккаунта сайта не включать: таких аккаунтов нет.
3. Проверить приём просмотров и трёх событий на тестовом прохождении. Не создавать
   несколько конверсий на одно действие одновременно через слой данных,
   автоматическое распознавание целей Метрики и визуальный конструктор.
4. Настройка «Автоматический поиск событий» управляется кабинетом VK, не кодом
   загрузчика. Проверить обнаруженные события и отключить ненужные: нельзя
   настраивать сбор содержимого описаний, черновиков и банковских заметок.

Установка кода не подтверждает настройки кабинета и фактический приём событий.
Тесты проверяют наши очереди и payload, но не внутреннюю работу стороннего SDK.
Вебвизор и карта кликов Яндекс Метрики остаются выключенными; её существующее
маскирование сохранено. Эти настройки Метрики не управляют пикселем VK.

## Выбор посетителя

`bereg:analytics-consent:v1` содержит только `accepted` или `denied` в localStorage.
Плашка не появляется повторно в том же браузере, пока данные не очищены.
Если хранение заблокировано, выбор действует в текущем окне; интерфейс сообщает,
что запомнить его не удалось. Записи случая и их ключи не меняются.

«Настройки cookie» в подвале позволяют изменить выбор. При отзыве согласия
события приложения блокируются сразу, Метрика деинициализируется. Для отключения
уже загруженных сторонних SDK предлагается явное обновление страницы. Перед ним
текущий случай сохраняется; ошибка сохранения или работа без сохранения блокируют
обновление, чтобы не потерять данные. Удаление прежних cookie или уже собранной
статистики не обещается. Изменения в другой вкладке также учитываются.

Плашка описывает текущие счётчики, но не заменяет политику обработки данных
с реквизитами оператора: таких реквизитов в исходниках нет.
